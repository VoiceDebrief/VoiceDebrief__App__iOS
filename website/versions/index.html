Release history

Every release of this repository. Every push to dev is a release: CI works out the next number from the latest tag, writes the version file, tags, and publishes the site. Nobody sets a version by hand (since 13 November 2026; before that the number was set in the push). A row headed next has not been given its number yet.

VersionDateWhat changed
v0.1.3914 November 2026The sgit app gains a gallery: a list of vaults to show somebody, by topic, each opened in the web Vault in a browser inside the app. The list is data, added on the device or read from a showcase.json in a vault; it ships empty. Also a picture of every screen of the sgit app from CI, and fixes those pictures called for.
v0.1.3514 November 2026A briefing when you open the app (issue 025): after an update, "Updated to this version: see what is new", linking to its page; and what happened since you last looked: new notes and their length, interrupted ones to run again, who notes were sent to, what was saved to your vault and what could not be. Worked out by the app from the library, not written by a model.
v0.1.3414 November 2026The sgit app: a vault is created on the device with no access token and no network, and takes files at once; sharing it sends it to the server, which is the first time a token is asked for. Forgetting a vault that is only on the device warns that it deletes it. In the engine, VaultSync can move a vault that holds large files. At the owner's request after the first run: the access key can be typed on the Create screen and the new vault goes to the server at once; files and folders can be dropped in from the desktop and dragged out; on an iPad or a Mac the folders are a tree down the left.
v0.1.3314 November 2026Vault keys and server tokens in iCloud Keychain, on by default (issue 017, the owner's decision). Each vault's key, each server and each token is now a Keychain item of its own, kept on this device and, unless a new switch under Keys on the Vaults tab is turned off, in iCloud Keychain too, so that a vault made on one device can appear on the owner's others and survive losing a device. A vault whose key has arrived says where the vault itself is: on its server, or still only on another device. Turning the switch off moves everything back to this device only. The key that signs a device's commits is never synchronised. In test: the logic is unit-tested with an in-memory Keychain; that Apple carries the items between two real devices has not been seen.
v0.1.3114 November 2026Where the work happens, on the record screen: one line for this device (listening, Apple's speech model transcribing, Apple's model writing the debrief) and one for the network (sending to whom, which part, encrypted), green while each is busy (issue 027).
v0.1.3014 November 2026Finish and send in one press: while recording, a button for each of your own recipients finishes the note, sends it as soon as it is written up, and leaves you on the record screen for the next one (issue 026). Sends now go one after another, so several notes sent in quick succession all go. A note remembers who it was sent to and when, on the note and in the list.
v0.1.2914 November 2026A version badge at the top of the record and library screens, beside the balance, opens this version's own page of what changed. CI now writes that page for every release from the notes headed next.
v0.1.2914 November 2026After review round 2: a recording can be shared or saved to Files from its note (039); deleting a note, throwing away a recording and sending to the developer ask with an alert that always shows how to say no (040); Diagnostics no longer offers a lane link that nothing used (041); the balance reads "Test credit" and says recording never stops (032); the send bar is shorter; a time reads 00:03, not 0:03; a note never transcribed offers "Transcribe and debrief".
v0.1.2913 November 2026Review round 1, the rest of this session's findings: a recording can start while the last note is still being written up; notes wait their turn and say so (issue 030). States say what to do: an interrupted note says to open it and run it again, a note with no debrief says why, an untranscribed note is no longer titled Recording, and the record screen promises it saves as you speak before you start (issue 036).
v0.1.2913 November 2026After the first review by synthetic users (round 1): a note opens with its one sentence as the heading and the date beneath; the clean text experiment moves below the transcript; every note with audio has a player, and tapping a transcript line plays from there; the send bar appears only when there is something to send, lists your own recipients first, names the built-in one as the developer of this test build, and says what goes; lists hold a readable width on iPad; Recent says the day; a cut title ends with an ellipsis; the toolbar says the language rather than its code; one line, not 1 lines.
v0.1.2913 November 2026Pictures of every screen (issue 016). A debug build launched with -VDSampleData is given invented notes in a temporary folder, a vault book in memory with one invented vault in the same folder, and no network, never the real library or Keychain, and -VDScreen opens a named screen; none of it is compiled into a release build. A UI test target takes one screenshot per screen, and a new workflow, screens.yml, runs it on an iPhone and an iPad simulator in light and dark and keeps the PNGs, with a contact sheet per set, as an artifact named by commit. Build, test and release says how to fetch them from a Linux container. Nothing a user sees has changed.
v0.1.2913 November 2026Identity (issues 005 and 018). PKIKit: the sgit key bundle in Swift (RSA-OAEP 4096 and ECDSA P-256, fingerprints, PKCS#8, keys under a passphrase, the k1 key code, detached signatures, statements, the signed envelope), proven in a new workflow where sgit pki and pki.sgit.ai's own keys.js read what Swift makes and Swift reads what they make. In the app, under Settings, an Identity screen: a key pair that says who you are, kept in iCloud Keychain so it reaches your other devices; a second key that says which device, kept in the Secure Enclave where there is one and ended by deleting the app; a statement, signed by the first and kept in a vault, that vouches for the second; and, optionally, a delegation from an identity at pki.sgit.ai, with the answer pasted back in. In test: none of it has run on a device, and debriefs are not yet signed by the device key.
v0.1.2013 November 2026Credit, on the pattern of newsroom.sgit.ai's meter (issue 008). A balance that starts at £5.00, is charged a little for just about everything the user does (a transcript by the minute, a debrief, a clean passage, creating a vault, each file saved to one, sending, and so on, in whole pence), and may go below zero with nothing blocked; recording is never charged. A counter on the Record and Library screens opens the credit screen: the balance, top-up, takings by feature, every entry, the prices. A charge can be declined with a reason. No money changes hands: the top-up is simulated and says so; paying through the App Store is written and switched off until the products exist. Every price is a placeholder. The ledger is a file on the device that nothing checks. Credit explains it, with what Apple requires. In test: not yet seen on a device.
v0.1.1913 November 2026A second app begins in this repository, for now: the sgit app (Apps/SGit, bundle ai.sgit.vaults.app), sgit as a native app, starting with photos, videos and large files into a vault. Its design and its own reality file are under sgit-app. The vault engine reads and writes files over 4 MB as sgit does (issue 023), encrypting from disk to disk, checked against sgit in both directions by a new workflow, sgit-app.yml. Nothing of the sgit app has run on a device. The version is now CI's, as in the other VoiceDebrief repositories: every push to dev is tagged with the next number, the version file and the README badge are written by CI, and the site is stamped when it is deployed. The app's TestFlight version is that tag.
v0.1.1713 November 2026The Lab, and its first experiment. Under Settings, a Lab section with L01, one prompt with tools on and off: type or pick a prompt, switch each tool on or off, and send one request to Apple's on-device model in a new session. The screen then shows everything: the instructions and prompt sent, the tools offered and kept back, each tool call with its arguments, result and time, the answer, the total time, and any error in plain words. Four tools that only read: the date and time, a list of notes, one note's transcript, and a choice of next screen that is recorded and not acted on. Six preset prompts say which tools a reliable model would call, and the screen counts how often it did. Runs are kept while the app is open and exported as JSON. Every request goes through one component, the model door, with a policy and a record; the debrief does not use it yet. In test: it compiles and its logic is unit tested, but CI has no model, so no request has been made.
v0.1.1513 November 2026After the owner's notes on build 0.1.9: the Send buttons are a bar fixed at the bottom of a note, where the growing transcript and debrief cannot move them, and a note sent before it is finished goes the moment it is. The version is shown on the record screen and links here.
v0.1.1313 November 2026Finishing a note saves it to a vault, at the owner's request (issue 022): once the note is done and its audio compressed, it is written into the vault chosen in Settings as one signed commit. On by default, with a switch; nothing happens until a vault exists. The note says where it was saved, or why it was not.
v0.1.1213 November 2026Vaults are local first, and a server is a remote. Creating a vault no longer asks for an access token: a vault is made, saved into, read and browsed on the device, with no server and no network. Servers are added by name, with an address and an access token in the Keychain; a vault has none or one. Push and pull are separate, explicit steps that only ever move a branch forward: when the device and the server have both changed, the app says a merge is needed (not built) and overwrites nothing. Each vault says where it is: on this device only, not yet pushed, on the server too, ahead of it, or push failed and why. Vaults made by earlier builds (from v0.1.5) stay on their server and work as before, and can be copied to the device. Forgetting a vault now asks first and says what would be lost. In test: none of this has run on a device, and nothing has been pushed to a real server from the app. CI has sgit clone a vault that was created in one folder and pushed to another.
v0.1.1013 November 2026The version is now CI's, as in the other VoiceDebrief repositories: every push to dev is tagged with the next number, the version file and the README badge are written by CI, and the site is stamped when it is deployed. The app's TestFlight version is that tag.
v0.1.913 November 2026Recipients. A note can be sent to anybody who has given you their lane: a person, another device, an agent session. Add one under Settings or from a note by scanning their QR code with the camera, choosing a picture of it, or pasting the link; the code may carry their name. A note has one Send button per recipient. A recipient's own QR code can be shown, to pass them on. The developer's lane built into the test build is the first recipient and still asks before sending; one you added yourself sends at once. For the other side, tools/conductor/conductor.py makes an inbox (a key pair, a vault, a lane), prints its link or QR code, and opens what arrives. The app now asks for the camera, only to read a QR code. In test: nothing here has run on a device. A later build of this version changes the record control, at the owner's request: it is green, and while recording shows a tick and finishes the note; Discard is a small red word at the top that asks before deleting.
v0.1.813 November 2026An experiment, at the owner's suggestion: a clean text. A note can be rewritten as full sentences by Apple's model, a passage of about 110 words at a time, with nothing meant to be left out. The model is given the speaker's own words (Settings, Your words), because Apple's speech model cannot be: SpeechTranscriber ignores contextual strings. It returns structure, not prose (guided generation), including up to three phrases per passage it could not follow, each with a question; an answer is kept and joins the speaker's words. The screen can show what was changed, word by word, and warns when a rewrite is under half the length of what was said. The clean text travels with a note sent over the lane. Also: the record screen follows the live words. In test: no clean text has been made on a device.
v0.1.713 November 2026Build A of the design: capture without loss, and a new shell. A note is created when recording starts and the recording is written straight into it as WAV, a form that can be repaired if the app dies before the file is closed; it is compressed only after the note is finished. A call or another app taking the microphone ends the recording and keeps it. Every note is kept on the device: a Library tab lists them by day and a note can be reopened, run again or deleted. Stopping opens the note at once and it fills in. Four tabs (Record, Library, Vaults, Settings) that become a sidebar on wide screens; a record screen with one large control; developer tools moved under Settings. The background audio mode is declared; recording with the screen locked is untested. A later build of the same version makes the record screen follow the live words, after the owner found they ran off the bottom.
v0.1.613 November 2026The debrief prompt again, after the first note sent over the developer lane: the model wrote "Speaker is..." and "[Speaker]" because the prompt itself said "the speaker". It now says the note is the reader's own, asks for plain statements with no subject, and marks the reader's tasks [me].
v0.1.513 November 2026Vaults. The vault engine can now create a vault, in the form sgit init writes; CI has sgit clone a vault Swift created. A Vaults tab: keep an SG/Send access token in the Keychain, create a vault, add one made elsewhere by its key, and look inside (head, files, history, branches, the key, and every request, decryption and signature check the engine made). After a run, save the debrief, transcript, run and audio into a vault as one signed commit. In test: no vault has been created from a device yet.
v0.1.413 November 2026The developer's lane is built into the test build, at the owner's request, so a note can be sent without pasting a link first; a pasted link still takes its place. Sending still happens only when the button is pressed.
v0.1.313 November 2026While recording: the words appear as they are spoken, and moving bars show the microphone is being heard. The live text is a preview; the transcript that is kept is still made from the recorded file when the recording stops. And a way to help judge the models: with a lane link pasted on the Diagnostics tab, a button after each run sends that note (audio, transcript and debrief) to the developer over an sgit append lane, encrypted on the device to the developer's key. Nothing is sent without pressing it.
v0.1.213 November 2026The debrief prompt, changed after the first real runs on an iPhone and a Mac: the model was copying quotation marks from the prompt's examples, renaming a heading, repeating a one-line note back as its own key point, and turning a passing remark into an action. The prompt now shows the shape with no quotation marks, says the speaker's own tasks are theirs, and says what is not an action. A note of fewer than 25 words is no longer sent to the model: the transcript is the whole note.
v0.1.113 November 2026The first feature, as the plan's quality spike: record a voice note or choose an audio file, transcribe it on the device with Apple's SpeechAnalyzer, and write a debrief with Apple's on-device model, reading a long note in parts. A diagnostics screen reports what the device says about both models and exports it. Nothing is saved yet. In test: nobody has judged the results on a device. Also: the TestFlight upload, proven by build 0.1.0 (4), installed on an iPhone and a Mac.
v0.1.013 November 2026The repository starts. An iPhone and iPad app that builds and tests, with one screen that says what is and is not built. The SGitVault vault engine copied from PrompTugal__App__iOS, with the door derivation made to work for any site and checked against the published vector. CI: build and test on a Mac, vault interop with sgit, and this site. The plan, published.
VoiceDebrief iOS

The VoiceDebrief transcript and debrief as a native iPhone and iPad app, on Apple's own models, with the results in a vault you own. In development: there is nothing to install yet. Content CC BY 4.0; code Apache 2.0.
