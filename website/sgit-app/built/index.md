# What is built in the sgit app

The reality file for the sgit app. **If it is not listed here as built, it does not exist.** The [design](../design/index.md) is intention; this page is fact, and it changes in the same commit as the code it describes.

Status words: [[built]] is in the repository and proven by a test that ran; [[unverified]] is written but has not been proven by a run (of CI, on a device, or against a server, as the row says); [[proposed]] does not exist.

## Built

Proven by `sgit-app.yml`, green in all three jobs since run 2 (13 November 2026) and on `dev` in run 7. Build 0.1.19 (7) was installed from TestFlight on a Mac by the owner on 14 November 2026 and opened: the empty list and the Create sheet were seen. Nothing else has been used on a device, and the app has not yet spoken to a server.

| What | Where | How it is tested |
|---|---|---|
| Files over 4 MB in the vault engine [[built]] | `Packages/SGitVault`: `VaultStreamCipher.swift` (AES-256-GCM as a stream, so a file is sealed and opened from disk to disk), `VaultLargeTransport.swift` (sgit's upload in parts and download in ranges), `VaultLargeFiles.swift` (staging, a commit of staged files, download with every check) | `LargeFileTests` on the CI Mac: the stream cipher byte for byte against CryptoKit; tampered files refused; a failed upload carried on; a lost race. `sgit-app.yml`: sgit clones a vault Swift wrote with files of 5 and 9 MB and verifies its signatures, and Swift reads a vault sgit wrote. All of that is against a folder. The exchange with the live server (signed URLs) is written and [[unverified]]: it has been run with sgit itself, not with the Swift code |
| The app builds and its tests pass [[built]] | `Apps/SGit/`: its own project, bundle `ai.sgit.vaults.app`, iPhone and iPad, iOS 26, SwiftUI, Apple SDK only | `sgit-app.yml`: a simulator build, a Release build for a device, unit tests on an iPhone and an iPad simulator |
| Adding files, underneath the screens [[built]] | `Engine/Outbox.swift`, `Engine/VaultShelf.swift`: a selection is copied in, encrypted to disk, uploaded and committed as one signed commit; a failed job is kept and is finished by a new `Outbox` after a restart; discard; a read key is refused; rename and delete as commits; what a commit changed; the signer's fingerprint | Unit tests on the simulators, against a real vault held in a folder: a 5 MB file read back byte for byte through the cache |
| TestFlight upload [[built]] | The last step of the Mac job in `sgit-app.yml`, with the release script: on a green push to `dev`, archive, sign and upload | Run 7 (13 November 2026) uploaded `ai.sgit.vaults.app` 0.1.19 (7), which the owner installed on a Mac. Run 14 (14 November) uploaded 0.1.34 (14): creating a vault without an access key, the access key on the Create screen, drag and drop, the folder tree. Run 20 uploaded 0.1.37 (20): the fixes the pictures called for. Run 25 (05:54 UTC) uploaded 0.1.39 (25): the gallery. Nobody has reported from any of the three yet |
| A vault made on this device [[built]] | `VaultShelf.create`, `sendToServer`; `VaultSync.transferWithLargeFiles` in the engine: created in a folder on the device with no access key and no network; files are added to it there; sending it to the server moves large files as files, and only then removes the folder; forgetting one that was never sent deletes it, after a warning | Unit tests on the simulators and the Mac (`sgit-app.yml` runs 9 and 10, 14 November 2026): create with no key, add, send to a folder standing in for a server, a second device opening it by key and reading a 5 MB file; a vault with a 6 MB file moved between two places. The screens for it, and the live server, are [[unverified]] |
| The access key on the Create screen [[unverified]] | `CreateVaultSheet`: a switch, on by default, puts the new vault on the server at once, and the access key is typed there if the app has none. Asked for by the owner on 14 November 2026. The app now says "access key", as the web Vault does | Compiles (`sgit-app.yml` run 10). Never used |
| Drag and drop [[unverified]] | `UI/VaultView.swift`, `Intake.keepAll`, `VaultShelf.itemProvider`: files and whole folders dropped on a folder are added to it, a folder keeping its shape; a file dragged out is fetched and decrypted when it is dropped | A dropped folder has a unit test. Dragging, in either direction, has never been tried |
| A folder tree on a wide screen [[unverified]] | `FolderTree` in `UI/VaultView.swift`: on an iPad or a Mac the folders are a tree down the left, as the web Vault has them, and the files of the chosen folder are on the right | The tree has a unit test. The screen has never been seen |
| A picture of every screen [[built]] | `Apps/SGit/UITests/ScreensTests.swift`, `Sources/App/LaunchSample.swift` (Debug builds only), `.github/workflows/sgit-app-screens.yml`: eighteen screens on an iPhone and on an iPad in landscape, each opened on an invented vault made by the real engine in temporary folders | Run 1 (14 November 2026) produced all 24 pictures. They are the only way any screen but the first two has been seen: on a simulator, with sample data, never with a server. Two faults they showed (thumbnails outside their tiles, a picture filling the file screen) were fixed; the run on `9b3f642` (26 pictures, thirteen screens) shows both fixed, and shows the standing line, Share on the toolbar and the gallery. The run on `50c8629` (34 pictures, seventeen screens) adds Create with no access key, a vault on this device only, files waiting to be sent and a key shown; all four were looked at and read as intended. The run on `d2cb5ce` (36 pictures) adds an upload refused for want of an access key, made by the app's own check |
| A gallery of vaults [[unverified]] | `Model/Gallery.swift`, `UI/GalleryView.swift`: a list of vaults to show somebody, by topic, with a search; each opens in the web Vault in the system's browser inside the app; one that carries a key can be added to the device's vaults. The list is what was added on the device (kept in the Keychain) and `showcase.json` from any vault on it. It ships empty | Compiles, and its unit tests pass on the simulators (`sgit-app.yml` on `f7dd58e`): the file in both shapes, the links, the grouping, reading it from a vault, keeping an added entry. Opening a real vault in the in-app browser has never been tried, and the screen has not been pictured |
| Vaults on the device [[unverified]] | `UI/VaultsView.swift`: add by key, read key or web link, pasted or scanned as a QR code; create; keys, access token and signing key in this app's Keychain | Compiles. The Keychain, the camera and the live server: never run |
| Adding photos, videos and files, the screens [[unverified]] | `Engine/Intake.swift`, `UI/VaultView.swift`: the Photos picker and the Files picker, progress for each file and the whole, Try again and Discard | Compiles. The pickers have never been used |
| Browsing [[unverified]] | `UI/VaultView.swift`, `UI/FileView.swift`: folders, a grid or a list, thumbnails for images, an image at full size, a video player, Quick Look, Save to Photos, Share, rename, delete | The listing has unit tests. The screens have never been seen |
| Saving a folder out [[unverified]] | `UI/VaultView.swift` (`saveOut`, `FolderExporter`): the three dots on a folder offer "Save these N files to Files" with the size; each file is fetched, laid out as in the vault and handed to the system's export sheet. The share sheet shows the line to paste on a computer (`pip install sgit-ai && sgit clone`) beside the shown vault key | The words and the paths have unit tests. Nobody has saved a folder on a device or a simulator |
| Sharing a vault [[unverified]] | `UI/ShareVaultView.swift`: the vault key and the read key as text and QR code, with what each gives; a link for the web Vault UI | The link's form has a unit test. Whether the web Vault UI opens a vault this app wrote has not been tried |
| History [[unverified]] | `UI/HistoryView.swift`: commits, signature, the signing key's fingerprint, whether it is this device's, what changed | What it shows has unit tests; the screen has never been seen |
