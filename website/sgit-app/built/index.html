What is built in the sgit app

The reality file for the sgit app. If it is not listed here as built, it does not exist. The design is intention; this page is fact, and it changes in the same commit as the code it describes. The guide in pictures shows the screens with the things to press numbered.

Status words: built is in the repository and proven by a test that ran; unverified is written but has not been proven by a run (of CI, on a device, or against a server, as the row says); proposed does not exist.

Built

Proven by sgit-app.yml, green in all three jobs since run 2 (13 November 2026) and on dev in run 7. Build 0.1.19 (7) was installed from TestFlight on a Mac by the owner on 14 November 2026 and opened: the empty list and the Create sheet were seen. Nothing else has been used on a device, and the app has not yet spoken to a server.

Files over 4 MB in the vault engine builtPackages/SGitVault: VaultStreamCipher.swift (AES-256-GCM as a stream, so a file is sealed and opened from disk to disk), VaultLargeTransport.swift (sgit's upload in parts and download in ranges), VaultLargeFiles.swift (staging, a commit of staged files, download with every check)LargeFileTests on the CI Mac: the stream cipher byte for byte against CryptoKit; tampered files refused; a failed upload carried on; a lost race. sgit-app.yml: sgit clones a vault Swift wrote with files of 5 and 9 MB and verifies its signatures, and Swift reads a vault sgit wrote. All of that is against a folder. The exchange with the live server (signed URLs) is written and unverified: it has been run with sgit itself, not with the Swift code

A gallery of vaults unverifiedModel/Gallery.swift, UI/GalleryView.swift: a list of vaults to show somebody, by topic, with a search; each opens in the web Vault in the system's browser inside the app; one that carries a key can be added to the device's vaults. Adding photos, videos and files, the screens unverifiedEngine/Intake.swift, UI/VaultView.swift: the Photos picker and the Files picker, progress for each file and the whole, Try again and DiscardCompiles. The pickers have never been used
Browsing unverifiedUI/VaultView.swift, UI/FileView.swift: folders, a grid or a list, thumbnails for images, an image at full size, a video player, Quick Look, Save to Photos, Share, rename, deleteThe listing has unit tests. The screens have never been seen
Saving a folder out unverifiedUI/VaultView.swift (saveOut, FolderExporter): the three dots on a folder offer "Save these N files to Files" with the size; each file is fetched, laid out as in the vault and handed to the system's export sheet. The share sheet shows the line to paste on a computer (pip install sgit-ai && sgit clone) beside the shown vault keyThe words and the paths have unit tests. Nobody has saved a folder on a device or a simulator
The web Vault inside the app unverifiedUI/WebVaultView.swift: "Open in the web Vault" on a vault's three dots and on a file. The page dev.vault.sgraph.ai/en-gb/vault/?embed=1 is loaded in a web view that keeps nothing, announces itself, and is handed the vault key by a posted message (the web Vault's embed protocol); the key is not in the address. It opens looking only. "Allow changes" hands the page this device's access key for the visit, after a warning; it is not offered for a vault that holds large files, because the web Vault rewrites a folder without the mark that says a file is largeThe protocol was tried on 14 November 2026 against the live page in Chromium with a throwaway vault made by sgit: opened by message, HTML preview shown, a deep link to a file honoured, nothing of the key in the address or in storage, and the access-key event turned "Read-only" into "Synced". The production host vault.sgraph.ai did not answer the handshake. The Swift has unit tests for the words and the host rule; the web view itself has never run on a device or a simulator
Your activity unverifiedEngine/UsageLog.swift, Engine/DeveloperLane.swift, Engine/LaneCrypto.swift (all three copied from VoiceDebrief), UI/ActivityView.swift under Settings: every screen opened and for how long, and about thirty actions (create, add, forget, send to the server, pick, retry, discard, open, share, show a key, save out, refresh), kept in a file on the device; a button sends the report, encrypted to the developer's key, over the developer's lane as sgit/usage/v1. Ids and times only: no file name, vault name or keyThe log, the report's shape and the lane message have unit tests. Nothing has been sent from a device, and nothing is sent without the button. Each device keeps and sends its own log; they are told apart by a random install id
Ask this vault, an experiment unverifiedEngine/VaultAsk.swift, UI/AskVaultView.swift, on a vault's three dots: one question to Apple's on-device model (Foundation Models), in a fresh session, which may call four tools that read a copy of the vault's listing and history (a summary, one folder, recent changes, files by name). Every call and what it returned is shown under the answer. The model is given names, sizes and commit messages, never a file's contents; it cannot change anything; nothing leaves the deviceThe tools have unit tests. The model has never been asked anything by this app: CI's simulators have no Apple Intelligence, and nobody has run it on a device. Whether its answers are any good is the experiment
Secrets unverifiedSources/Secrets/: a Secrets row on the home list; every vault with a secrets/ folder, grouped, searchable; kinds login, device passcode, Wi-Fi, card, note, token, vault key, read key, access key, recovery codes; add, change and delete, each one signed commit of one encrypted JSON file (sgit.ai/secret/v1), read into memory, never into the file cache; hidden values behind Face ID or the passcode, copied for two minutes; "Make a strong password"; "My secrets" made on this device with the first secret; the app covered when not in front (the home stack; a sheet open at the time is not yet covered)Unit tests for the format, the paths, the kinds and the password maker; written before its CI run, so not yet compiled when this row was written. Nobody has used it on a device. Sync between devices (issue 122), sharing with people (124) and AutoFill (125) are not built
Questions for you unverifiedUI/QuestionsView.swift, Resources/sg-questions.json: questions from the people building the app, on the home list and in Settings; answer by choosing, typing, or the keyboard's dictation; sent sealed over the developer's lane as sgit/answer/v1Unit tests for the bundled questions and the lane message; not yet compiled when written; nothing has been sent from a device
The same vaults on every device unverifiedEngine/SecretStore.swift (two homes, after VoiceDebrief's), Engine/VaultShelf.swift: each vault that is on a server is also kept as its own iCloud Keychain item, and the access key too, so an iPhone, iPad and Mac on one Apple account open the same vaults with nothing to set up; a vault only on one device is not carried until it is on the server; new vaults from other devices are picked up when the app comes to the front, and vaults already open are read again then; forgetting a vault takes it out of iCloud Keychain; a switch in Settings. "My secrets" is marked by a file so another device finds it, and goes to the server at once when there is an access keyUnit tests with two simulated devices sharing one iCloud Keychain. Never run across real devices. iCloud Keychain carries items on Apple's schedule, usually within a minute
Sharing a vault unverifiedUI/ShareVaultView.swift: the vault key and the read key as text and QR code, with what each gives; a link for the web Vault UIThe link's form has a unit test. Whether the web Vault UI opens a vault this app wrote has not been tried
