What is built in the sgit app

The reality file for the sgit app. If it is not listed here as built, it does not exist. The design is intention; this page is fact, and it changes in the same commit as the code it describes.

Status words: built is in the repository and proven by a test that ran; unverified is written but has not been proven by a run (of CI, on a device, or against a server, as the row says); proposed does not exist.

Built

Proven by sgit-app.yml, green in all three jobs since run 2 (13 November 2026) and on dev in run 7. Build 0.1.19 (7) was installed from TestFlight on a Mac by the owner on 14 November 2026 and opened: the empty list and the Create sheet were seen. Nothing else has been used on a device, and the app has not yet spoken to a server.

WhatWhereHow it is tested
Files over 4 MB in the vault engine builtPackages/SGitVault: VaultStreamCipher.swift (AES-256-GCM as a stream, so a file is sealed and opened from disk to disk), VaultLargeTransport.swift (sgit's upload in parts and download in ranges), VaultLargeFiles.swift (staging, a commit of staged files, download with every check)LargeFileTests on the CI Mac: the stream cipher byte for byte against CryptoKit; tampered files refused; a failed upload carried on; a lost race. sgit-app.yml: sgit clones a vault Swift wrote with files of 5 and 9 MB and verifies its signatures, and Swift reads a vault sgit wrote. All of that is against a folder. The exchange with the live server (signed URLs) is written and unverified: it has been run with sgit itself, not with the Swift code
The app builds and its tests pass builtApps/SGit/: its own project, bundle ai.sgit.vaults.app, iPhone and iPad, iOS 26, SwiftUI, Apple SDK onlysgit-app.yml: a simulator build, a Release build for a device, unit tests on an iPhone and an iPad simulator
Adding files, underneath the screens builtEngine/Outbox.swift, Engine/VaultShelf.swift: a selection is copied in, encrypted to disk, uploaded and committed as one signed commit; a failed job is kept and is finished by a new Outbox after a restart; discard; a read key is refused; rename and delete as commits; what a commit changed; the signer's fingerprintUnit tests on the simulators, against a real vault held in a folder: a 5 MB file read back byte for byte through the cache

A gallery of vaults unverifiedModel/Gallery.swift, UI/GalleryView.swift: a list of vaults to show somebody, by topic, with a search; each opens in the web Vault in the system's browser inside the app; one that carries a key can be added to the device's vaults. The list is what was added on the device (kept in the Keychain) and showcase.json from any vault on it. It ships emptyCompiles, and its unit tests pass on the simulators (sgit-app.yml on f7dd58e): the file in both shapes, the links, the grouping, reading it from a vault, keeping an added entry.
