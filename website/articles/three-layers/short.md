**Kind:** a position, in short. From the owner, 15 November 2026: "what we run at each layer is the superpower."

Three things in this project can do work, and the skill is giving each step of a job to the lowest one that can do it well.

## 1. The code

The Swift in the app. Exact, instant, free and offline, but it only does what somebody wrote.

- Keeps every recording from the first second, and repairs one cut short.
- Owns every state: recording, waiting, written up, sent.
- Counts the briefing ("2 new notes since you last looked"), so it is always true.
- Hears "send this now" at the end of a note from a fixed list of phrases.
- Encrypts, signs and syncs vaults.

## 2. Apple's model on the device

Speech recognition and the Foundation Models framework, on the iPhone, iPad or Mac. Free per use, private, about a second; but small, and lost on long or rambling notes.

- Transcribes (6 minutes 44 seconds of speech in 5.4 seconds on an iPad).
- Writes the debrief.
- Labels a note while you speak: who it is for, topic, urgency (Lab L04).
- Picks one action from a sentence, compared with fixed phrases (Lab L02).

## 3. Agents in a loop

Claude sessions and the conductor, working through lanes and vaults. They read, plan, build and act; but take minutes, cost per run, and see only what is sent to them.

- Receive notes sent to Claude, sealed on the device.
- Reply under the note, through a vault you gave them.
- Report what they are doing in Agents, with decisions for you.
- Build this app: a voice note becomes an issue, code, and a release card.

## A note, end to end

Code records and keeps it. The model on the device transcribes and labels it. Code seals and sends it. The conductor files it, acts on it and replies. Code shows the reply under the note.

Each handover is a file, a sealed message or a commit you can see; nothing is left in a model's memory.

The full article, with a drawing and a table of where each thing belongs, is on the project's site.
