# 039: A copy off the phone that anyone can make

**Status:** open. From review round 2 (14 November 2026, `website/reviews/round-2/index.md`). **Owner:** the main session (the note screen); the vaults session for what a vault on a server adds.

New finding 1. Screens `note.finished-end`, `vaults`. Found by the user who lost a recording elsewhere; with the
player in place it is the one thing that still decided them against keeping a recording only here.

A note's words can be shared ("Share the debrief and transcript"). Its audio cannot: there is no export, no
"Save to Files", no share of the recording. The only other copy is a vault, and the sample's vault is "On this
device only": a second copy on the same phone. Beyond that is a form for a server's address and an access token,
which this user could not fill in. An interrupted note, the one most at risk, is not saved to a vault until it
has been run again.

To do: share the recording itself from the note (the system share sheet, so Files, AirDrop and Mail all work),
on every note that has audio, including an interrupted one. Say on the vault, in plain words, that a vault on
this device is not a backup until it has a server.
